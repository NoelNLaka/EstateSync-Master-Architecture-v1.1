      This separation is mandatory

      Cloudflare should answer “should this traffic reach the application?”. Supabase Auth answers “who is this user?”. PostgreSQL RLS answers “can this user access this row?”. Each is useless as a substitute for the others.

      What the edge cannot do. A rate limit can slow an abusive client; it cannot decide whether that client is entitled to a given tenant’s rows. That decision stays inside PostgreSQL, which is why the architecture keeps the perimeter, the identity provider and the authorization boundary in separate hands.

      • perimeter controls are probabilistic and tuned against real traffic
      • identity is a claim about a session, not an entitlement to data
      • RLS is the only layer that sees the row being requested
      • audit and monitoring detect what the others could not prevent
